FIREBASE SETUP (accounts, cloud sync and AI)
Accounts and sync work on the free Spark plan. The AI features use a Cloud Function, and Cloud Functions need the Blaze (pay as you go) plan.
Gemini 2.5 Flash calls are small, and each person is limited to 60 AI calls a day, but set a budget alert anyway (Google Cloud console > Billing > Budgets).
Without Blaze the app still works completely. The three AI buttons simply do not work.

A. ACCOUNTS AND SYNC
1. console.firebase.google.com > Add project (Google Analytics off).
2. Build > Authentication > Get started > Sign-in method > Email/Password > enable the first switch > Save.
3. Build > Firestore Database > Create database > Production mode > nearest region.
4. Project settings (gear) > General > Your apps > Web (</>) > register the app > copy the config values into firebase-config.js.
5. Authentication > Settings > Authorized domains: add your hosting domain (YOUR-PROJECT.web.app is there already).
6. Open the app and create your own account. Authentication > Users > copy your User UID.
   In Firestore start a collection named admins, Document ID = that UID, one field: on (boolean) = true.
   Only admins can then read all users, all feedback, and write strategies.

B. DEPLOY (hosting + rules + AI function) from a computer
1. Install Node 22 and the CLI:  npm install -g firebase-tools   then   firebase login
2. In this folder: edit .firebaserc and put your project id in place of YOUR-FIREBASE-PROJECT-ID.
3. Get a Gemini API key at aistudio.google.com/apikey, then store it as a secret (it is never put in any file):
      firebase functions:secrets:set GEMINI_API_KEY
4. Install the function's packages:   cd functions && npm install && cd ..
5. Deploy everything:   firebase deploy --only hosting,firestore:rules,functions
   The first functions deploy asks to enable a few Google APIs. Say yes.
6. Open https://YOUR-PROJECT.web.app, log in, then Plan > "Ask AI Coach to adjust my week".

C. CONNECTING GITHUB
Firebase Hosting can deploy from GitHub: run   firebase init hosting:github   once. That workflow publishes the website files only.
The AI function and the rules are not published by it, so run step B5 again whenever functions/index.js or firestore.rules changes.
Do not commit your Gemini key anywhere. It lives only in Secret Manager.

HOW IT WORKS
- Your plan, tasks, sessions, day capacity, timer, study logs and AI history are one document: users/{uid}/data/state. Rules let only that person read or write it.
- Every change is saved to this phone first, then to your account about half a second later. The Firestore offline cache keeps changes made offline and sends them when you are back online.
- When you log in on another phone, the newest copy is loaded. While the app is open, changes from your other phones arrive live.
- Old accounts: the plan stored at states/{uid} is read once and moved to the new place on the next save. After everyone has updated you can delete the states rules.
- The browser calls /api/ai with your login token. The function checks the token, counts the day's calls, calls Gemini with the secret key, and returns JSON. The browser can only ask for three fixed tasks (split, quiz, coach), not send its own prompts.

HOW LOGIN WORKS
- Username + password become a hidden email (username@aimsarthi.invalid) in Firebase Authentication. Passwords are handled by Firebase.
- The favourite number is stored only as a salted PBKDF2 hash in users/{uid} and is checked after the password is accepted.
  It is a weak extra check (few possible answers), so the password is the real protection.
- Forgotten password: no email reset exists (the email is made up). Reset the person in Authentication > Users instead.

DATA FOR YOUR DEVELOPER APP (collections)
users/{uid}            username, contactEmail, createdAt, lastActive, exam, examDate, level, daysUsed, streak, tasksTotal, tasksDone, minutesStudied, app
users/{uid}/data/state each person's full plan as JSON text, readable only by that person
aiUsage/{uid_day}      daily AI call counter, written only by the function
feedback/{id}          uid, username, type (problem|suggestion), message, contact, exam, app, status, createdAt
strategies/{id}        sourced topper entries the roadmap engine learns from (fields listed in strategies.js; add weights:{Subject:1.5} if you like).
                       Set verified:true only after checking the source. The engine needs 20 verified entries per exam before it uses them.
