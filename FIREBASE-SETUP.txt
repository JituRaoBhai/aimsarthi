FIREBASE SETUP (free Spark plan; Cloud Functions are not used)
1. console.firebase.google.com > Add project (turn Google Analytics off). Stay on the Spark plan.
2. Build > Authentication > Get started > Sign-in method > Email/Password > enable the first switch > Save.
3. Build > Firestore Database > Create database > Production mode > nearest region.
4. Firestore > Rules tab > replace everything with the text of firestore.rules > Publish.
5. Project settings (gear) > General > Your apps > Web (</>) > register the app > copy the config values into firebase-config.js
   (on GitHub: open the file > pencil icon > edit > Commit).
6. Authentication > Settings > Authorized domains > Add domain: YOUR-USERNAME.github.io
7. Open the app and create your own account. Then Authentication > Users > copy your User UID.
   In Firestore start a collection named admins, Document ID = that UID, one field: on (boolean) = true.
   Only admins can then read all users, all feedback, and write strategies.
8. Reopen the app twice so the phone loads the new firebase-config.js.

HOW LOGIN WORKS
- Username + password become a hidden email (username@aimsarthi.invalid) in Firebase Authentication. Passwords are handled by Firebase.
- The favourite number is stored only as a salted PBKDF2 hash in users/{uid} and is checked after the password is accepted.
  It is a weak extra check (few possible answers), so the password is the real protection.
- Forgotten password: no email reset exists (the email is made up). Reset the person in Authentication > Users instead.

DATA FOR YOUR DEVELOPER APP (collections)
users/{uid}      username, contactEmail, createdAt, lastActive, exam, examDate, level, daysUsed, streak, tasksTotal, tasksDone, minutesStudied, app
feedback/{id}    uid, username, type (problem|suggestion), message, contact, exam, app, status, createdAt
strategies/{id}  sourced topper entries the roadmap engine learns from (fields listed in strategies.js; add weights:{Subject:1.5} if you like).
                 Set verified:true only after checking the source. The engine needs 20 verified entries per exam before it uses them.
states/{uid}     each person's full plan as JSON text; readable only by that person.
